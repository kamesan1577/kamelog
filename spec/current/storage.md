# 保存先と移行

保存方式はローカルSQLiteと媒体ディレクトリ、またはCloudflareのSQLite-backed Durable Objectsを選べる。
ブラウザに正本を保存せず、既存の投稿URLと媒体URLを維持する。
クラウドを選んだ場合もアプリと動画変換は現在のサーバーで実行する。

## 移行対象

既存DBの全テーブルを対象とする。
公開投稿だけでなく、下書き、プロフィール、パスキー、セッション、設定、閲覧数、いいね、タグ、推論ジョブ、ActivityPubの秘密鍵と配送待ちデータを含める。
画像と動画は既存のIDとファイル内容を保つ。
再取得可能なFediverse画像キャッシュのファイルは正本に含めず、移行後に必要に応じて再取得する。
参照元のリモート投稿、媒体の対応表、公開条件はDBとともに移行する。
アプリの実行環境に置く暗号鍵と接続トークンはソースコードや公開APIへ含めない。

## 移行の完了条件

1. 書き込みを止め、元データの整合バックアップを作成する。
2. 空のクラウド世代へ全件転送する。
3. 全テーブルの内容と件数、全媒体のサイズとハッシュ、DBと媒体の参照を照合する。
4. クラウド側の世代を確定し、保存先を一度だけ切り替える。
5. 新しい保存先で再開する。

一部のデータだけをクラウドへ切り替える状態を作らない。
失敗時は元データを削除せず、同じ移行を再開するか、切り替え前に取り消す。
移行済みの古いローカルDBへ通常の投稿処理が書き込むことを禁止する。

## 投稿時の通知

利用上限に達した場合は、保存できなかった理由と再試行の条件を投稿画面の既存toastに表示する。
入力内容を保持し、保存成功として投稿画面を閉じない。
容量、書き込み枠、リクエスト枠の制限を検出した場合は`storage_limit`を返す。
認証や上流サービスの内部エラー文字列をそのまま画面へ出さない。

通信が切れて保存結果を確認できない場合は、その旨を表示して投稿一覧の確認を促す。
移行中、競合、設定不備、データ検証の失敗もそれぞれ識別できる固定メッセージを返す。

## 非公開媒体と可搬性

媒体は非公開のDurable Objectsへ保存し、画像と動画は既存の認可を通したアプリのAPIから配信する。
Workers Freeを使い、R2と有料プランを要求しない。無料枠を超えた操作は停止する。
媒体容量の既定上限は全世代合計3,000,000,000 bytesとし、DBを含むアカウント全体の無料枠も確認する。
下書きと未投稿の媒体はオーナーだけが取得できる。
動画のRange配信を維持する。

クラウドの最新データをSQLiteと媒体のアーカイブへ出力し、別の空ディレクトリへ復元できる。
新たな保存アダプターは、この復元形式と投稿の原子的な保存を維持する。
