# エラー表示と投稿画像（Issue #95）

## エラー表示

- 投稿などの一時的な操作失敗は既存の Sonner toast に表示する。通信失敗や 401/403/404/409/413/429 は `lib/api-error.mjs` で次の操作が分かる日本語に揃える。
- ユーザーがその場で直す必要がある入力・Fediverse 設定・カメラ・Mermaid 記法のエラーは、対象の近くに inline で表示し、内容を保持する。
- ページ単位の予期しない描画エラーは `app/error.tsx` のデザインシステム `ErrorState` で「もう一度試す」（Next.js `reset`）と「ホームへ戻る」を表示する。root layout 自体のエラーは `app/global-error.tsx` で復帰できる。
- デザインシステム内で `ErrorState` を compact 表示して主要コンテンツの再取得失敗にも流用できる。内部例外・認証トークン・リクエスト本文を UI に表示しない。
- ページエラーは404と区別し、404ページの表示・ステータスを変更しない。

## 画像の最適化

既存の `components/image-upload-bridge.tsx` が通常のブラウザ投稿を最適化する。JPEG/PNG/WebP は長辺2560px以内、WebP品質0.88への変換を試み、変換後の方が大きければ元ファイルを使う。GIFはアニメーションを維持する。変換失敗時は元ファイルをアップロードする。

サーバーは画像のMIME、署名、サイズ12MiB以内、寸法上限およびピクセル数を従来どおり検証した上で、ブラウザの処理を迂回した場合だけ不足分を補う。

- 長辺2560px以内かつメタデータのないWebPは、再エンコードせずbytesをそのまま保存する。
- 同条件の256KiB未満の画像もそのまま保存する。
- それ以外の静止画はFFmpegでWebP品質84への変換を試みる。長辺2560pxを超えれば縮小する。EXIF/XMP等を検知した場合はメタデータ除去を優先する。
- 縮小もメタデータ除去も不要で、変換後が元より大きければ元を保存する。
- GIFおよびアニメーションWebPはフレームを失わないよう元のbytesを保持する。アニメーションのメタデータ除去・寸法縮小はこの変更の対象外。
- 保存するファイルは一時ディレクトリで準備し、媒体IDで配置する。メタデータ永続化に失敗したら配置済みファイルを削除する。失敗した変換の不完全なファイルは残さない。
- `/api/media/:id` のURL、公開条件、保存されたMIME/拡張子/寸法/サイズを一致させる。既存画像は変更しない。マイグレーション・環境変数追加は不要。Dockerに既に含まれるFFmpegを使用する。

## 検証

静止画像の縮小と圧縮、EXIF除去、GIF/アニメーションWebPの保存、既に最適化されたWebPの無変換、保存失敗時の削除をサーバーテストで確認する。Storybookでpage/inlineエラーを確認し、既存の投稿・画像E2E、`make check` と `make e2e`、DockerビルドをCIで確認する。
