# ADR 0012: つぶやきの親参照と30日オーナーセッション

## 状況

つぶやきをXのスレッド / Zenn Scrapの追記に近い形で連結したい。また、オーナーログインが12時間で失効しており、個人サイトの日常運用には短い。

## 決定

- つぶやきの連結は別テーブルを追加せず、投稿JSONの任意 `parentId` で既存tweetを参照する。
- `parentId` はtweetだけに許可し、作成後は不変とする。通常の更新payloadが `parentId` を省略してもサーバーが既存値を保持する。
- 表示側は親をたどり、子は `parentId` で組み立てる。複数の子を許容して分岐可能な木として扱う。
- 追記UIは既存の巨大な投稿コンポーネントへ構造変更を入れず、投稿詳細に小さなクライアント橋渡しコンポーネントを追加する。`app/globals.css` は変更しない。
- オーナーセッションはSQLiteの `sessions` に引き続き保存し、有効期限を12時間から30日に延長する。cookieとDBのTTLは同じ共有定数を使う。
- セッションはDockerコンテナではなく永続データディレクトリに属するため、volumeを保持する通常デプロイでは失効させない。明示logout、期限切れ、認証リセットで失効する。

## 理由

投稿そのものが親IDを持つ方式なら、単一オーナー・SQLite・公開投稿中心という現在の規模で追加の結合テーブルや移行を必要とせず、バックアップ形式もそのまま維持できる。親を不変にすることで循環や意図しない付け替えを避けられる。

30日の固定セッションは、毎日の管理操作でパスキー認証を繰り返す負担を減らしつつ、無期限cookieにはしない妥協点である。HttpOnly / SameSite=Strict / HTTPS時Secure、Origin検証、明示logoutは維持する。

## 影響

- schema versionの変更は不要。既存投稿は `parentId` なしのrootとして扱う。
- 将来、スレッド単位のタイトル、close/archive、並び替え等が必要になった場合は専用thread entityへの移行を再検討する。
