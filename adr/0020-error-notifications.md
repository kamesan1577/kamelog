# ADR 0020: サーバーエラー通知の分離と秘密情報保護

- 状態: 採用
- 日付: 2026-09-20

## 背景

オーナーはサーバーで発生したエラーをDiscord等で受信し、対象サービス・最低ログレベル・送信先をアカウント画面から変更したい。公開リポジトリにWebhook認証トークンを置かず、通知経路障害を投稿処理に波及させない必要がある。

## 決定

通知元は固定イベント (`service`, `level`, `code`) だけを通知層へ渡し、通知層が送信先アダプター (Discord/Slack/JSON) を選ぶ。元イベントの例外メッセージ、stack、HTTPリクエストの値は外部へ転送しない。通知設定とWebhook暗号文は既存の永続SQLiteに分離保存し、ホスト側で既に自動生成される `KAMELOG_INFERENCE_ENCRYPTION_KEY` を再利用してAES-256-GCMで暗号化する。owner-onlyの管理ページとAPIはURLを再表示せず、保存・削除・テストの操作のみ提供する。

Webhook URLはHTTPS、正規provider host/routeおよび接続時DNSの公開IPを検証し、private networkにアクセスさせない。外部応答本文を読み出さず、redirectを追わず、送信失敗を呼出元に伝播させない。連続同一エラーは短期間集約し、同時送信数を制限する。ログの閾値と対象サービスは独立設定する。

## 選ばなかった方式

- URLをGit/環境変数に置く: 管理画面で変更できず公開漏洩のリスクが増える。
- 任意のログ文字列やstack traceを転送する: 利用者データ・認証情報が流出し得る。
- リクエストと同期してWebhook送信する: 配信先の遅延・障害でサイトを巻き込む。
- 任意のprovider URLを検証なしでfetchする: 内部ネットワークへのSSRFにつながる。

## 限界

インプロセス通知であり、ホスト停止・Docker/systemd障害や致命的なプロセス終了時の配信成功は保証しない。必要なら独立した監視プロセスを追加する。暗号化鍵はDBとは別に保管し、復元環境にも安全に移す。
