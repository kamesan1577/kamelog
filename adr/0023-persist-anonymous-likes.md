# ADR 0023: 匿名いいねをサーバーへ保存する

## 状態

採用。

## 背景

kamelog上のいいねはブラウザの `localStorage` にだけ保存され、そのブラウザの表示件数へ加算されていた。
サーバーへ送信する経路がなく、他の閲覧者にはActivityPub経由のいいねだけが反映されていた。

## 決定

`POST /api/posts/:id/like` で `{ clientId: UUID, liked: boolean }` を受け付け、公開投稿へ匿名でいいねを設定または解除できるようにする。
同一Origin、JSON入力検証、いいね専用の全体rate limitを要求する。
一般ユーザー登録やowner sessionは要求しない。

schema 12で `local_post_likes` tableを追加し、投稿IDとclientIdを組み合わせたSHA-256 hashで重複を防ぐ。
生のUUIDやIPアドレスは保存せず、投稿削除時には対応recordも削除する。
recordの追加または削除に成功した場合だけ、既存の投稿JSON内のlocal likesを同じtransactionで増減する。
同じ状態の再送は冪等とし、投稿revisionと日時を変えない。
ActivityPub由来の件数は従来どおりquery時に合算し、local likesへ書き戻さない。

ブラウザは新しい保存キーで匿名識別子と保存成功済みの押下状態を記憶し、件数にはサーバーの合計値を使う。
API失敗時は押下状態を確定せず、既存のエラー通知を使う。
ボタンの配置や見た目は変更しない。

## 移行と制約

旧 `kamelog-likes` は各ブラウザにしか存在せず、過去のいいねをサーバー側で回収できない。
旧状態を自動で一括送信せず、修正後の操作から記録を始める。
既存のサーバー保存済みlocal likesは保持する。

UUIDは本人認証ではない。
識別子の削除、端末変更、新しいUUIDの生成による再いいねは防げないため、人物単位の厳密な投票としては扱わない。
匿名識別子を失うと、その識別子で付けたいいねを解除できなくなる。
SQLiteのbackup/restoreでは件数と重複防止recordを一緒に保存し、再起動後も同じ操作を二重加算しない。
